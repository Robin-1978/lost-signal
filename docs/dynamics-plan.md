# 动力学与去硬编码实施计划

> 状态：阶段一~四、DIY 车库、轮胎/电机库均已实施并验证（见提交记录）。
> 剩余：阿克曼/履带（第一章关闭后）、20 关批量（管线就绪）、桌面验收/远端 CI/8 人测试（需人工与远端）。对应讨论：驾驶风格条（无极 s∈[0,1]，三预设点分段插值）、
> 动力学三件套（电机+摩擦+惯性）、底盘配置化动态加载。
> 原则：内容归 JSON、契约归代码；官方配置结论不变，绝对数值漂移后重标定基线（已刷新 validation）。

## 背景

当前动力链（`src/sim/motor_drive.cpp:30-73`）是单差速模型：
twist → 轮速 → CPR=2048 编码器量化 → 双轮速 PID → PWM → 加速度限幅 → 运动学。
电机完整，摩擦只有里程计噪声代理（`mission_simulation.cpp:489-499`），惯性只是一阶加速度钳位；
自行车模型是死代码，履带不存在。同时一批行为参数硬编码在 C++ 里（航向 PID、能耗系数、
到达判定、地面标签等）。

## 阶段二 动力学三件套（行为变化，独立提交 + 重标定）

### 0. PID 自适应整定（前提，DIY 的地基）
机库允许 DIY 装配（不同轮胎/电机/车身，未来还有新底盘），固定增益不可维护。
规则：PID 增益 = 装配物理参数的纯函数，同装配必得同增益，确定性天然成立；
`ro1.json` 里现有的 `speed_pid` 固定值删除，只留安全封顶。
* 轮速环：按单轮一阶模型 `dv/dt=(K·PWM−v)/τ`（K、τ 由 F_stall、m、v_free 推导），
  用极点配置/IMC 取闭环带宽（目标 settling ~0.3s，具体公式写进设计文档），
  输出 Kp/Ki/Kd；积分限幅与输出 ±1 保留为安全帽。
* 航向环：由轮距、巡航速度、加速度上限推导 P 主导 + 航向误差微分，
  输出钳在 `w_max`。
* 校准锚点：整定规则调到 RO-1 默认装配算出接近现验证值（轮速 1.8/0.35/0.01 量级），
  把基线漂移压到最小；漂移部分仍按正常流程重标定 validation。
* 新增回归：遍历全部轮胎 × 计算单元装配，断言无持续 PWM 饱和振荡、
  官方配置结论不变。以后加新电机/新底盘只需写 JSON 物理参数，PID 自动跟上。

### 1. 惯性
`ro1.json:drive` 新增 `mass_kg`、`yaw_inertia_kgm2`。单轮纵向：
`F = PWM·F_stall·max(0, 1−|v_w|/v_free)`，`a_w = (F − F_res) / (m/2)`。
横摆维持运动学换算（低速差速足够），惯性体现在轮速一阶响应滞后上。

### 2. 摩擦（轮胎 × 地面综合）
* `tires.*.behavior` 新增 `friction_mu`（胎面：防滑 0.9 / 标准 0.7 / 节能 0.5）、`rolling_resistance`。
* `surfaces[]` 新增 `material`（形状仍用 `type`）、`friction_mu`（混凝土 0.8 / 玻璃 0.3 / 水 0.2 / 砂石 0.6）、`rolling_drag`。
* 合成：`μ_eff = μ_tyre × μ_ground / μ_ref`；滑移率 `s=(ωr−v)/max(|v|,ε)`，
  牵引力 `F=μ_eff·N·sat(s/s_c)`，超附着部分转成打滑标志 → 里程计噪声与制动距离。
* 现有 `slip_scale`（里程计故事）、`brake_decel`（DWA 制动包络）保留，文档注明推导关系，
  本期不合并，避免基线一次性全变。

### 3. 电机扭矩曲线（高转低扭 / 低转高扭）
`ro1.json:drive.motor` 新增 `stall_force_N`、`free_speed_mps`，
即上式中的 `F_stall` / `v_free`，反电动势自然包含。`max_accel` 保留做安全封顶。
纯电气细节（扭矩-转速精细曲线、电压跌落）明确不做。

验收：官方配置结论不变（推荐全通且评分不变、默认终关动态碰撞），
允许绝对时间/净空漂移；漂移后刷新 `docs/validation.md` 基线表；
`test_mission_simulation` 结构断言全绿（它不断言绝对时间，只断言确定性）。

## 阶段三 底盘配置化动态加载

* `ro1.json:drive.type` 已存在（现为 `"differential"`），以此为分发点定义小接口：
  twist 进 / 位姿出 / 双执行器遥测（PWM、RPM），与现有快照字段兼容。
* `DifferentialMotorDrive` 成为该接口的第一个实现；未知 `type` 直接 `ContentError`，
  不写空壳占位。
* 已实施：`ChassisModel` 接口泛化遥测 + `AckermannDrive`（驱动电机环 + 转向舵机位置环，
  自行车运动学，原地不打转）+ `test_chassis` 回归；`drive.type` schema 放开枚举。
  出战线缺第一辆阿克曼内容车（参数+官方配置+重标定），随第二章来；工厂分支与内容同到。

### 阿克曼底盘（第一章关闭后，第一顺位）
* JSON：`drive.type="ackermann"` + `steering{delta_max_deg, steer_rate_max_dps,
  servo_response_s}`，沿用电机/编码器/质量字段；PID 自整定天然覆盖转向舵机
  （一阶模型换时间常数即可）。
* 仿真：自行车运动学（`tanδ` 转弯，最小转弯半径显式出现）+ 前轮侧偏刚度近似；
  DWA 采样空间换成 `(v, δ)`，倒车/原地转向能力消失——这是和差速手感差异最大的点，
  也是第二章的教学点。
* 车库：新增“底盘”栏（差速/阿克曼二选）；认知层多画最小转弯半径圆。
* 验证：至少一套官方通关配置 + 重标定（转弯半径改变全部路线净空）。

### 履带底盘（阿克曼之后）
* JSON：`drive.type="tracks"` + `track{width_m, contact_length_m, lateral_slip}`。
* 仿真：滑移转向 + 纵向/侧向滑移率模型（阶段二的摩擦框架直接复用，
  这就是摩擦先行的原因）；原地转向回来了，但掉头刮地、湿滑横摆是新失败模式。
* 验证同上。注意：履带没侧滑模型根本没法开，所以阶段二摩擦是前置条件。

### 电机槽位（本轮正在实施，不属于底盘）
* 电机是“动力”槽位组件（标准/扭矩/高效），不是底盘：三种电机 × 现有差速底盘；
  阿克曼/履带到来时直接复用同一电机库（参数含义不变：堵转力/自由转速/功耗比）。
* L4/L5 `required_slots` 加 motor，L5 预算 6→7（推荐配置顶格所致，只调天花板，
  不改仿真）；标准电机进初始库存，扭矩/高效随 blocked 通关授出。

## 阶段四 关卡规模化（20~100 关，独立计划）

手写 5 关可行，手写 100 关必崩。生产方式换成管线，一切仍走 JSON（手写与生成同一格式，
同一校验），不硬编码。

### 1. 关卡生产管线
* **模板化**：现有 5 关恰好是 5 种题型（校准 / 感知 / 定位 / 规划 / 动态组合）。
  每种做成带参数的模板：目标距离、障碍密度、叉车速度与数量、湿滑区大小、时限与预算；
  新关 = 模板 + 参数 + 剧情皮。
* **生成器**（`tools/` 新增）：按难度曲线批量生成关卡 JSON，种子固定 → 输出确定，
  可 review 可 diff。
* **批量平衡报告**：`headless × 全关卡 × 候选配置` 一次跑完，输出时间/净空/能耗/评分表；
  调平衡看表调参，不进游戏。100 关 headless 实测应在分钟级，有可以直接计入 CI 门禁。

### 2. 内容架构复用
* 地图/场景/GLB 共享：多关共用 `research_base` 类式基地，通过供电/障碍/巡逻配置
  改变状态，不为每关建新场景（设计文档既定方向）。
* 难度只用已验证的旋钮：时限、预算、净空阈值、能耗阈值、叉车速度/数量、湿滑系数、
  传感器噪声种子。**不引入新机制**：关卡只加参数不加代码。
* 章节解锁图保持列表式（`campaign.json:levels` + `prerequisites`），100 关内无需改结构；
  超过再考虑章节分组字段（预留，不先做）。

### 3. 规模化验证
* `validate_content.py` 按关卡数线性扫描：ID 唯一、引用存在、解锁无环、预算可行、
  每关至少一套官方配置可通关（跑 headless 断言，非人工）。
* 性能门禁：内容校验 + 全关全通 ≤ N 分钟（N 待定，先测出 5 关基线再外推）。
* 生成关卡同样进 `tests/new` 回归，种子固定。

### 4. 可玩性来源（只用数据表达）
* 多解：每关至少两套可通关配置（现有断言，沿用）。
* 三独立评价 + 最佳成绩持久化（已有，沿用）。
* 关卡变体：同一模板换种子/换时段（灯光/雾参数已在场景 JSON）/换预算，零代码新增。
* 禁止的：随机种子不固定、一次性加成类 modifiers 进代码、排行榜/社区关卡
  （设计文档明确 MVP 外，本期不做）。

## 顺序与提交

1. 阶段一去硬编码 → 验证 SHA 不变 → 提交。
2. 无极风格条（行为层插值，锚点行为不变）→ 提交。
3. 阶段二动力学（含 PID 自适应整定）→ 调参保结论 → 刷新 validation 基线 → 提交。
4. 阶段三接口接缝 → 提交。阿克曼/履带另起章节计划。
5. 阶段四关卡模板 + 生成器 + 批量平衡报告 → 提交。20 关首批后，再谈 100 关与变体系统。

## DIY 车库（基础模块，与阶段一~三并列，已部分实施）

机库从“按关配给”升级为 DIY：通关奖励 → 玩家库存 → 栏位按“关卡开放 × 库存拥有”过滤；
装配跨关持久（每关记住上次装配）。

* 内容（已实施）：初始库存收缩为三件套；boot 授 eco/grip/双雷达，
  localization 授性能算力与沙地/竞速胎；validator 跨关拥有检查 + 奖励合法性。
* C++（本轮实施）：`CampaignProgress` 持有真实库存（通关合并组件奖励，幂等）、
  存读 `inventory` + `last_builds`；`GameUi` 按库存过滤选项、切关恢复上次装配。
* 轮胎库（已实施）：5 种轮胎，L4/L5 栏位可选；`test_content_catalog` 计数 10。
* 电机库（已实施）：动力槽位（标准/扭矩/高效）+ L4/L5 required + 栏位 + L5 预算 6→7；
  电机参数进执行器与自整定，能耗乘功耗比；官方配置沿用标准电机，数值零漂移。
  新电机×算力已验证协同（扭矩+轻量算力撞车，扭矩+性能算力 64.98s 通过）。
* 地面库（排后）：第二张图出现时收成 `assets/surfaces.json` 材质库。
* 底盘库（第一章关闭后）：阿克曼/履带各需独立参数 + 官方通关配置 + 重标定。

## 与无极风格条的衔接

风格 s∈[0,1] 在温柔 0 / 普通 0.5 / 激进 1 三点分段线性插值，保证官方推荐/默认
（落在锚点上）行为逐比特不变。插值对象是行为层（巡航、净空、前视、加速度上限），
不碰 PID 增益。阶段二的质量/μ 参数位在风格实现时预留，风格条先做行为层插值。
