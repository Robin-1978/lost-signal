# Production verification coverage

This ledger answers a narrower question than a mission result: which smallest layer establishes each production
model or algorithm claim? A row may cite a deterministic mission as coupled evidence, but never as its only oracle.
The detailed fidelity limits remain in [Simulation model audit](simulation-model-audit.md); release commands and
results remain in [Validation](validation.md).

Status meanings:

- **Focused:** a contract or invariant is checked at its owning layer with an analytic result, independent derivation,
  property, or deliberately different implementation.
- **Component:** focused checks exist and the relevant provider/runtime boundary is exercised.
- **Partial:** useful checks exist, but a named edge, fault, calibration, or independent oracle is still missing.
- **Planned:** the production capability is not yet allowed to make the claim.

Simulator truth may measure error in a test or headless diagnostic. It may not enter a ROBOT production decision,
track association, planner input, or normal localization observation.

## Change rule

Before a new production implementation is enabled by content or a recommended build:

1. add or update its row above;
2. state one canonical unit/frame/time/data-ownership contract;
3. add a focused test with an independent oracle and a no-solution or boundary case;
4. add provider/interface fault cases when data crosses a boundary;
5. only then add deterministic mission evidence;
6. keep the remaining physical or algorithmic limit explicit.

A green mission cannot close a red or partial row. If a correct focused model changes a mission outcome, the model
stays correct and the content expectation is reassessed.
